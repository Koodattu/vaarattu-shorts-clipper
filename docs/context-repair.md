# Repairing clips that need context

The review queue's **Needs more context** button opens two independent controls, **← Before** and **After →**, and an optional note (up to 2,000 characters). Neither checked lets the model choose either side; one checked limits extensions to that side; both allow either side. The note can identify a missing question, referent, setup or qualification.

**Find missing context** queues a worker action using the recording's existing provider, verification reasoning setting and remaining spending limit. The app never starts inference while the form is merely open. The original preview and review decision remain unchanged while the request runs. You can stay to see the result automatically, or **Skip** and keep reviewing; refresh the queue after processing to revisit the clip. Like existing clip edits, the recording's current job must finish before another context request can be queued for it. Other recordings can use the normal job queue.

The model sees the current caption text, the human note, directions, and original timed words surrounding the cut. It looks up to 90 seconds before and after, reducing that to 60 or 30 seconds if the provider's input budget requires it. It returns only an expand/unchanged recommendation, two source word IDs and a short Finnish explanation. The system validates IDs, chronological overlap with the existing moment, allowed directions, actual added speech, whole-word cuts and a maximum source duration of 90 seconds. The current interval is retained in full. It cannot rescue an unrelated discussion by switching to another moment, invent context, or rewrite speech.

If no useful extension is found, the same revision and preview stay available with the explanation in review notes. If useful context exists, the worker creates a new pending revision, renders it through the existing alignment/pacing/caption pipeline, and returns it unapproved for human review. Previous exports remain accessible. No discovery score gate or per-video count allocation is rerun for this human-requested repair.

The whole-VOD Turbo transcript and original discovery anchors remain intact. For runs with final large-v3 transcription enabled, an expanded excerpt gets a fresh final transcription after the context LLM exits, before rendering. Earlier manual captions remain in the previous revision; the expanded revision's large-v3 captions are regenerated and should be reviewed. Without that option, existing caption corrections keyed to the same Turbo words carry into the expanded interval. Pause cuts continue to use transcript timestamps only.

Requests, input snapshots, model responses and validated results are retained under `workdir/runs/<run_id>/context-repair/<request_id>/`. The database saves the current request and reason with the clip. Revision/request checks prevent duplicate or stale application. Model cache and stage checkpoints avoid repeating completed inference after a pause; durable operation flags route retries back to context repair or rendering even if the displayed stage changed to final transcription. Model/provider/budget failures leave the request pending and the original preserved: open the run and resume/retry when the issue is resolved. Pause/cancel retain completed work and can be resumed through the run controls.

Offline tests cover direction combinations, source/length validation, unchanged results, preserved prior decisions/exports, new unapproved revisions, retry routing and review controls. Actual repair quality still needs evaluation on user-requested jobs. No app, live LLM call, ASR or media render was started during implementation.
